# 계획 도구

도담 1.0까지의 계획 문서와 일정 시뮬레이션을 만드는 스크립트다.

- **작업 분해**는 `wbs_data.py` 하나에 있다. 일마다 날짜 · 앞선 일 · 산출물 · 끝났다는 표시 · 맡는 쪽 · 공수가 있고, `base_start` · `base_end`는 시뮬레이션이 늘리기 전의 계획 길이다.
- **문서 다시 만들기**: `sh build_all.sh`. 날짜 · 앞선 일 순서 · 코드 같은 표기를 검사한 뒤 `docs/plan`의 Markdown과 HTML을 다시 쓴다. 검사에 걸리면 멈춘다.
- **일정 다시 재기**: `python3 montecarlo2.py`, `python3 scen.py`, `python3 anchors.py`로 경우별 결과와 이정표의 가운데 · 80% 날짜를 다시 내고, `python3 retime.py`로 작업 날짜를 가운데 추정으로 옮긴 뒤 `sh build_all.sh`를 돌린다.
- **가정**(구독 용량, 일 길이가 늘어나는 정도, 위험의 확률과 기간, 측정이 쓰는 구독 용량)은 `montecarlo.py` 위쪽에 숫자로 있다. 잰 값이 나오면 이 숫자를 고친다.
- **페이지 검사**: `python3 check_page.py <html> <폴더>`로 휴대폰 · PC 화면과 밝은 · 어두운 테마에서 에러와 가로 넘침을 본다(Playwright 필요).
- **같은 숫자를 다시 내기**: 씨앗과 횟수가 스크립트에 적혀 있어서 같은 명령은 같은 숫자를 낸다. 이정표 날짜는 `python3 anchors.py`(씨앗 2029, 2,000번), 용량과 측정을 바꾼 경우들은 `python3 scen.py`(씨앗 11, 1,200번씩)다. 시범이 바꾼 12월 일정과, 씨앗에 따라 날짜가 얼마나 움직이는지는 `python3 pilot_replan.py`가 낸다(일정은 씨앗 5개로 2,000번씩, 1.0까지의 예측은 씨앗 5개로 1,200~2,000번씩, 몇 분 걸린다). 예측은 그것을 낼 때 있던 일만 굴린다. 그 뒤에 더한 일은 `wbs_data.py`에 `added`로 날짜를 적어 두고 예측에서 뺀다. 날짜를 다시 잡을 때 함께 넣는다.
- **헌장 v0.7이 적었던 날짜 다시 내기**: `python3 claude_only.py`(씨앗 11, 경우마다 1,200번, 네 경우를 한 씨앗에서 차례로 뽑는다). Claude 하나 · 나눠 쓰는 경우 · 두 회사의 날짜와, 같은 경우를 씨앗 10개로 돌린 비교를 `claude_only.json`에 쓴다. `python3 claude_only.py --check`는 전부 다시 계산해 그 파일과 같은지 알려 준다(몇 분 걸린다). `python3 pilot_replan.py --check`도 같은 일을 `pilot_replan.json`에 한다. 테스트는 일정의 첫 씨앗만 다시 계산한다. 나머지 씨앗과 경우, 1.0까지의 예측, 씨앗 10개 비교는 이 두 명령이 확인하고, CI의 `recorded` 작업이 푸시마다 둘 다 돌린다(작업마다 시간 한도의 절반 안에 끝나도록 나눠 돌린다. `pilot_replan.py`는 `--part schedule`과 `--part forecast`로, `claude_only.py`는 `--part 1/3` · `2/3` · `3/3`으로 나누고, 부분을 합치면 전체다). 씨앗과 경우는 프로세스를 나눠 나란히 돌리는데, 저마다 자기 씨앗에서 새로 시작하므로 몇 개를 함께 돌리든 결과가 같다.
