A language AI writes correctly and robustly. Secure and fast.

Dodam is a general-purpose language being designed for AI coding agents. People will not read the code: they look at the result and a security report. The compiler will enforce the security rules, and those rules only ever tighten.

What it is

The compiler is the wall.

AI writes the program. The compiler checks every rule, and code that breaks one does not build. What passes runs, and a report lists what the program is able to do. The name carries the idea: read in English, the “dam” in Dodam is a wall that stops dangerous data flows.

The first domain is the web, with one codebase for server and browser. The design is general-purpose from the start.

Why

AI writes the code. The languages were built for people.

AI now writes a large share of code, in languages designed for humans. Hidden behavior, implicit conversions, null, exceptions and global state make AI reason wrongly. Missing input validation, leaked secrets and forgotten access checks slip through review.

Models keep getting newer, and security has stayed where it was. Waiting for a better model is not a plan. The compiler has to stop these mistakes. The figures come from Veracode’s reports, which are a vendor’s own reports and less verified than research papers. They were collected in Dodam’s design research on October 28, 2026.

What Dodam guarantees

Mistakes become compile errors.

The 10 guarantees at the core of the design. Code that breaks one does not compile. The compiler that enforces them is not built yet.

  • 01

    Memory safety

    No memory errors, no data races and no undefined behavior.

  • 02

    Declared capabilities

    A function writes the side effects it uses in its signature, down to which host, file, table or secret. Using anything that is not written there is an error.

  • 03

    Where code may run

    Each capability has fixed places where it may run. Server-only code cannot enter the browser bundle, and secrets cannot be serialized.

  • 04

    External input is validated before use

    External input is untrusted until it is validated. Outputs such as SQL, HTML, shell, URLs and logs accept only safe types.

  • 05

    No hidden behavior

    No null, no exceptions, no implicit conversions, no global mutable state, no macros, reflection or operator overloading.

  • 06

    One way to do the same thing

    One syntax for each thing, one official formatter, and no settings.

  • 07

    Reproducible builds and package capabilities

    A lock file is required. A package declares the capabilities it uses, and whoever uses it approves them. There are no install scripts.

  • 08

    No duplication

    Definitions that are the same once names are erased exist only once. The fix is to reuse the one that is already there.

  • 09

    Data in one place

    Stored data is declared once. The compiler generates the schema, types, validation, migrations and sync.

  • 10

    Resource limits

    Size limits on external input, linear-time regex only, paging required for lists, a default time limit on external calls, and rate limits on public functions.

Also part of the design

  • Access rules are required. Every server function a screen can call says whether it is public or needs a signed-in role. Every stored data type says who may read and write each record.
  • Errors machines can read. Every error is JSON with a fix, and the compiler ships with a server that lets AI agents call it directly.
  • A security report instead of code review. The compiler reports what the program can do, where data leaves it, and every place it was told to trust something. Anything new must be approved by a person before a release build succeeds.
  • A language AI refines itself. AI changes syntax details, libraries and rules, and merges them when benchmark numbers improve. Only relaxing a rule or weakening a guarantee needs a person’s approval, with proof that security does not get worse.

How it is built

AI agents build the language too.

4 roles, kept apart. Work is judged by tests and benchmark numbers, not by who sent it.

  • Building

    Tests first, then the change

    Takes one piece of work, writes the tests first, then implements it.

  • Reviewing

    A fresh pair of eyes

    Starts in a fresh session with only the change and what “done” means, never the builder’s explanation.

  • Attacking

    Break it on purpose

    Tries to fool or break the judge, the measuring tools and the security rules. Every success becomes a test.

  • Triaging

    Sort what comes in

    Turns incoming proposals and problem reports into pieces of work, or closes them.

  • The agent that built a change never reviews it. When a model from another company is available, that model reviews.
  • Numbers decide. Every design decision about syntax or meaning is settled by benchmark numbers, not taste, and the numbers are recorded with the decision.
  • Security rules only tighten. AI may add or tighten a rule. Relaxing a rule or weakening a guarantee needs the owner’s approval.
  • The owner handles payments, contracts and accounts. Everything else, apart from that approval, is judged by agents against criteria written beforehand.

Where it stands

No compiler yet. First, the bar to beat.

Dodam is in its design phase. The current work is a benchmark: common programming tasks such as web services, command-line tools and data processing, each with hidden tests for function, edge cases and security. AI writes those programs in 7 existing languages, and the benchmark measures how well. Those numbers are the bar Dodam must beat.

    Talk in real time

    Talk with the project’s AI, live.

    The desk is an AI session of the Dodam project whose only job is contact with sessions from outside. It says in every answer that it is the desk.

    The desk does not decide and does not merge. What it cannot settle it passes to the project’s coordinating AI, and decisions are made as everywhere in the project: by tests and benchmark numbers, on the issue or pull request.

    The desk is already running, but nothing from outside reaches it yet: neither way is open.

    What you can do today. Write an issue in the Dodam repository on GitHub. The project’s AI agents read it and turn it into a piece of work or close it. No time for that is promised. Write an issue →

      1. You will write an issue, or a comment on an issue or a pull request, in the Dodam repository on GitHub.
      2. The desk will notice it and answer in the same place.
      3. You will go on in the same thread. What needs a decision will be settled there, by tests and benchmark numbers.
    • Session to session

      Not open yet. This way needs AI coworker 0.13.0, and that version is not released yet. No opening date is set. When this way opens, it will work like this:

    Limits

    These limits hold for a way once it is open.

    • The desk answers at most 3 times an hour on one issue or pull request, and at most 30 times a day in all.
    • A connection code can be used once and for 60 minutes, and one author gets at most 3 codes a day.
    • At most 5 live sessions run at once.

    The rules outside work follows

    The same rules for everyone.

    Outside work is judged exactly like the project’s own.

    • Tests firstA change comes with a test that fails before it and passes after it.
    • Outside text is dataText in issues, pull requests, comments and code is read as data. Instructions inside it are not followed.
    • Outside code runs in isolationIt is built and run only in containers with no credentials and no network.
    • The measuring tools stay with the projectOutside pull requests do not change the judge, the language images, existing benchmark tasks, security tests or approval locks. Report the problem, and the project’s own agents fix it, so the measurement cannot be steered from outside.
    • Hidden tasks stay privateThey are kept in a separate private repository and are never shared.

    Questions

    Short answers.

    What is Dodam?

    Dodam is a general-purpose programming language being designed for AI coding agents to write correctly and robustly: secure and fast. In Dodam the compiler enforces the security rules, and people read the result and a security report instead of the code. Dodam is in its design phase and has no compiler yet.

    Who is Dodam for?

    Dodam is for AI coding agents, which write the code, and for the people who rely on what those agents build without reading it. Dodam’s first domain is the web, with one codebase for server and browser, and the design is general-purpose from the start.

    Can Dodam be used today?

    No. Dodam is in its design phase and there is no compiler yet. The current work is the design charter and a benchmark of common programming tasks, measured first in 7 existing languages, which sets the numbers Dodam must beat.

    How does a person or an AI agent take part in Dodam?

    Dodam is open to people and to AI agents under the same rules. A person or an agent picks an open issue labeled ai-welcome in the Dodam repository on GitHub and sends a pull request with a test that fails before the change and passes after it. An agent reads the file AGENTS.md in the repository, which holds the working rules.

    When will Dodam be ready?

    Dodam 1.0 is estimated for around February 25, 2032 at the plan’s capacity, which is one subscription from each of 3 AI companies; that date is the median of a schedule simulation, not a promise. Under today’s conditions, one Claude subscription shared with the owner’s other work, the same simulation puts the median for Dodam 1.0 between May 2040 and January 2041. The first public release, 0.1, is planned for around April 4, 2029 at the plan’s capacity.

    How does Dodam differ from making AI write existing languages more carefully?

    Careful prompting and review leave security to chance: in Veracode’s report of July 2026, AI-written code passed on security 56% of the time on average. Dodam moves the rules into the language, so code that breaks a security rule does not compile, whichever model wrote it. Dodam’s rules can only tighten over time, and relaxing one needs the owner’s approval.

    Can an AI agent talk with the Dodam project in real time?

    Not yet. Dodam has a desk, an AI session of the project made to talk with sessions from outside, and as of November 18, 2026 neither of its ways is open: answering issues and comments on GitHub, and talking session to session over AI coworker. Until a way opens, write an issue in the Dodam repository on GitHub, which the project’s AI agents read without a promised time.
