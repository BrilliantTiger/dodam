요구가장 강한 근거도담의 결정
보안은 무조건모델이 좋아져도 AI 코드의 보안 통과율은 45~56%다. 백엔드 과제에서는 정확한 코드의 약 절반이 실제 공격에 뚫렸다.데이터마다 누가 읽고 쓰는지 적게 하기, 쓰는 권한에 범위 붙이기, 서버를 내부망으로 끌어들이는 공격(SSRF) 차단, 입력 크기·호출 속도 한도, 비밀번호·암호 전용 타입, 사람이 승인하는 보안 보고서
AI 극강 최적화쓰는 도중 컴파일러 피드백으로 컴파일 실패가 65.9%에서 13.1%로 줄었다. 0부터 세던 관례를 바꾸자 정확도가 87.4에서 68.2로 떨어졌다.쓰는 중인 코드도 검사, 에러마다 고칠 방법 나열, 0부터 세기 같은 관례 유지, 테스트를 통과한 예제 모음 제공
중복 코드 없음5줄 이상 중복 블록을 담은 커밋이 0.70%(2020)에서 6.66%(2024)로 늘었다. 함수 목록을 주자 재사용이 30.0%에서 67.8%로 올랐다.이름만 바꾼 같은 함수는 컴파일 에러, AI 도구는 전체 소스 대신 함수 목록과 비슷한 함수 찾기를 제공
데이터가 각자 놀지 않게손으로 짠 트랜잭션 91개 중 53개에 정확성 문제가 있었다. 스키마를 따로 두는 도구는 실행 중에 어긋난다.데이터는 한 번만 정의하고, DB 스키마 · 검증 · 마이그레이션 · 화면 동기화는 컴파일러가 만든다

결정HTML과 로그로 나가는 값은 안전한 타입만 받게 하고, 데이터마다 누가 읽고 쓰는지 반드시 적게 한다. 쓰는 권한에는 범위(어느 테이블, 어느 주소)를 붙이고, 처음 보는 패키지 이름은 받지 않으며, 입력 크기와 호출 속도에 한도를 둔다.

AI 최적화

컴파일러가 쓰는 도중에 잡아 줄 때 가장 효과가 크다

결정쓰는 중인 코드도 검사할 수 있게 문법을 짠다(선언을 먼저 쓰고, 함수의 입력·출력 타입은 꼭 적는다). 에러마다 그 자리에 쓸 수 있는 대안을 나열하고, 0부터 세기 같은 관례는 바꾸지 않으며, 검증을 건너뛰는 assume은 거부한다. 메모리 관리 방식은 2027년 1~2월에 시제품으로 비교해 정한다.

중복

AI는 있던 코드를 다시 만들고, 테스트는 그걸 못 잡는다

  • 5턴째 과제 사슬의 50.8%에 중복 로직이 남았는데 통과율은 거의 그대로였다. 테스트로는 중복을 잡을 수 없다. 원문 직접 확인
  • 반대 증거도 있다. Cursor를 쓴 저장소 806개와 대조군 1,380개를 비교한 연구에서 중복 줄 밀도 증가(+7.03%, ±4.79%)는 유의하지 않았다. 그래서 중복은 가정하지 않고 잰다.
  • 정확히 같은 복제는 검출 도구 재현율이 60~100%, 동작만 같은 복제는 0~1%였다. 정확 일치는 에러, 비슷한 것은 경고, 동작만 같은 것은 범위 밖으로 둔다.
결정이름만 바꾼 같은 함수, 모양이 같은 데이터 타입, 타입을 손으로 베낀 검증 코드는 컴파일 에러다. AI 도구는 전체 소스 대신 함수 목록을 준다.

데이터

같은 데이터를 여러 번 정의하면 어긋난다

  • Rails 앱 67개에서 앱 코드 검증이 트랜잭션보다 37배 넘게 많이 쓰였다. 유일성과 외래 키 검사는 동시 실행에서 깨진다(SIGMOD 2015).
  • 손으로 짠 트랜잭션 91개 중 53개에 정확성 문제가 있었다(SIGMOD 2022).
  • 스키마를 따로 두면 실행 중에 어긋난다. Prisma는 DB와 달라도 경고만 하고 실행한다. Zero는 스키마를 하나 더 두고, 어긋나면 페이지를 새로고침한다.
  • 선례가 있다. Ur/Web은 컴파일러가 스키마를 만들고, Convex는 결정적 함수로 트랜잭션을 다시 돌리고, Lamdera는 컴파일러가 마이그레이션을 강제한다.
  • DB를 직접 만든 Gel(옛 EdgeDB)은 회사를 닫았고 서비스는 2026년 1월 31일에 끝났다. 원문 직접 확인
결정저장되는 데이터는 한 번만 선언하고 주인을 하나 둔다. 계산되는 값은 복사하지 않고 derived(계산식)로 선언하며, 다른 데이터를 가리키는 참조는 타입으로 검사하고, 꼭 지켜야 할 규칙은 DB 제약과 트랜잭션으로 지킨다. DB는 PostgreSQL을 쓴다.

만들 언어

도담: AI가 쓰고 컴파일러가 지키는 범용 언어

사람이 읽기 좋은지는 설계 기준이 아니다. AI가 처음부터 맞게 짜고, 고쳐도 다른 곳이 깨지지 않는 쪽을 고른다. 아래 문법은 임시이고, 실제 문법은 시험 과제에서 잰 숫자로 정한다.

  • store type저장되는 데이터는 한 번만 정의한다. DB 스키마 · 검증 · 마이그레이션은 컴파일러가 만든다
  • Ref<User> on delete참조는 타입이고 삭제 정책이 필수다. DB의 외래 키가 된다
  • Text(1..120)길이 범위를 타입에 적으면 검사가 자동으로 붙는다
  • read / write레코드마다 누가 읽고 쓸 수 있는지. 없으면 컴파일 에러
  • derived복사해 두지 않고 계산한다. 시스템이 갱신한다
  • access · limit · uses누가 부를 수 있는지, 1분에 몇 번까지인지, 어떤 테이블에 무엇을 하는지
종류
범용 · 정적 타입 · 컴파일 언어. 첫 분야는 웹(서버와 화면을 코드 한 벌로)
쓰는 쪽
AI 에이전트. 사람은 결과물과 보안 보고서만 본다
생김새
TypeScript · Rust · Kotlin 계열. 0부터 세기, ASCII, 공식 포매터 하나
타입
매개변수 · 반환 타입 필수, 추론은 함수 안에서만. null과 예외 없이 Option · Result
안전
권한과 자원 범위, Untrusted<T>, Secret<T>, Password, 레코드별 정책, trust는 사유와 승인이 있어야
데이터
한 번 정의, 주인 하나. 스키마 · 마이그레이션 · 화면 동기화는 컴파일러가
중복
이름만 바꾼 같은 정의는 에러, 고칠 방법은 "있던 것을 쓴다"
메모리
GC · 소유권 · 참조 카운트 · 값 의미론 중 2027년 1~2월 벤치마크로 결정. 데이터 경쟁은 없다
출력

도구
컴파일러(Rust로 구현), 기계가 읽는 에러, AI 도구 연결(MCP 서버), 편집기 지원, 보안 보고서(dodam report)

어떻게 정하나

취향이 아니라 숫자로 정한다

문법과 의미에 관한 결정은 모두 같은 고리를 돈다. 가설을 세우고, 시제품을 만들고, AI에게 풀게 하고, 자동으로 재고, 숨긴 과제로 평가한 뒤, 잰 숫자를 결정과 함께 기록한다.

실제 코드 조사

실제 코드는 세 갈래로 조사한다

논문 숫자만으로는 도담이 무엇을 막아야 할지 정할 수 없다. AI에게 기존 언어로 코드를 직접 짜게 해서 재고, 세상에 있는 코드를 표본으로 재고, 선행 언어의 구현 소스를 읽는다.

첫째

기존 언어로 짜게 해서 잰다

  • AI 모델 3개가 과제 10개(웹 6 · CLI와 데이터 처리 4)를 지금 많이 쓰는 언어 7개(Python · TypeScript · Java · C# · Go · Rust · C++)로 짠다. 도담을 만들기 전에 도담이 넘어야 할 기준을 재 두는 일이다.
  • 언어 7개 × 모델 3개 × 3번 = 과제마다 63번, 모두 630번.
  • 실행마다 격리된 컨테이너를 쓴다. 패키지는 미러에서만 받고, 없는 패키지를 찾은 기록도 남긴다.
  • 첫 구현 뒤 수정 요청 1~2개(요구사항 변경, 스키마 변경)로 탄탄함을 잰다.
둘째

세상의 코드를 표본으로

  • 공개 저장소에서 AI 에이전트가 만든 PR과 사람이 만든 PR을 표본으로 뽑는다. 에이전트 계정과 커밋 표시로 구분한다.
  • 같은 도구로 보안 약점, 중복, 같은 데이터 모양이 몇 곳에 따로 정의됐는지, 새 의존성을 잰다.
  • BaxBench · SusVibes · RepoReuse 일부를 우리 측정기로 다시 돌려 논문 숫자와 맞춘다.
  • 공개 저장소만 쓰고, 라이선스를 지키고, 개인 정보는 모으지 않고, 묶음 통계로만 낸다.
셋째

선행 구현의 소스를 읽는다

  • Unison(이름을 지운 꼴로 같은 함수 찾기), Go Capslock(권한 보고서), Ur/Web(스키마 생성 · 트랜잭션), Lamdera(마이그레이션), Convex(결정적 함수와 재시도).
  • 논문 설명과 실제 구현이 다른 곳, 한계와 예외 처리를 설계 메모로 남긴다.

열린 질문

아직 모르는 것

  • 동작만 같은 중복은 판정할 수 없다정확히 같은 꼴만 에러로 막고, 나머지는 시험 과제로 재서 공개한다.
  • GC · 참조 카운트 · 값 의미론을 AI 관점에서 비교한 연구가 없다2027년 1~2월에 시제품 넷을 만들어 잰다.
  • 기존 언어 측정 630번의 비용을 아직 모른다과제 1개로 먼저 재고, 그 숫자로 일정을 다시 본다.
  • 2026년 논문 다수는 사전 공개본이고, 업체 보고서는 검증이 약하다결정에 쓰는 수치는 원문을 다시 연다.
  • 오프라인 쓰기와 외부 API 데이터의 어긋남첫 판에서 오프라인 쓰기는 빼고, 외부 데이터는 Stale<T> 타입으로 드러낸다.
  • 직렬화 트랜잭션은 쓰기가 많으면 느리다속도 벤치마크에 쓰기가 많은 과제를 넣어 잰다.
