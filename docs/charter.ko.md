# 도담 헌장 — 0단계 설계 초안

- 판: v0.3 (2026-10-28)
- 상태: 초안. 검토하면서 고친다. 공개 전에 영어판을 만든다.
- 바뀐 내용과 이유: 16절 판 이력

## 1. 한 줄 정의

**AI가 정확하고 탄탄하게 짤 수 있는, 안전하고 빠른 범용 언어.** 사람이 읽을 필요가 없는 언어다. AI가 AI를 위해 스스로 다듬고, 사람은 결과물과 보안 보고서만 본다. 보안 규칙은 컴파일러가 강제하고, 그 규칙은 시간이 갈수록 조여지기만 한다. 첫 분야는 웹이고, 서버와 화면을 코드 한 벌로 쓴다.

> A general-purpose language that AI writes correctly and robustly: secure, fast to run and fast to compile. No human needs to read it: AI refines it for AI, and people look only at the result and a security report. Security is enforced by the compiler, and the rules only ever tighten. Its first domain is the web, with one codebase for server and browser.

## 2. 이름

**도담 (Dodam).** "도담도담"은 아이가 탈 없이 튼튼하게 자라는 모양이다. 이 언어도 탈(보안 사고) 없이, 스스로 자란다. 영어로 읽으면 끝의 `dam`(막는 벽)이 위험한 데이터 흐름을 막는다는 뜻으로도 읽힌다.

- 명령어: `dodam`
- 파일 확장자: `.dodam`

## 3. 누구를 위한 언어인가

- **사용자는 AI 코딩 에이전트**다. 사람은 코드를 읽지 않는다. 사람이 보는 것은 결과물(돌아가는 프로그램)과 보안 보고서(5절)다.
- 사람이 읽기 좋은지는 설계 기준이 아니다. 문법 · 진단 · 도구는 모두 AI가 가장 잘 쓰는 쪽으로 고른다.
- **범위는 범용**이다. 웹에만 묶지 않는다. 도구와 라이브러리는 아래 순서로 넓히지만, 메모리 모델 · 타입 · 권한 같은 핵심 설계는 처음부터 4번 분야까지 감당하도록 정한다.

| 순서 | 분야 | 시작 |
|---|---|---|
| 1 | 웹 — API 서버와 브라우저 화면 | 2027년 1월 |
| 2 | CLI 도구 · 데이터 처리 | 2027년 7월 |
| 3 | 네트워크 서비스 · 시스템 프로그래밍 | 2028년 |
| 4 | 임베디드 · 게임 · 고성능 수치 계산 | 1.0 이후 |

### 목표의 뜻

- **AI가 개발하기 쉽다** = 정확하고 탄탄하게 짠다.
  1. 정확도 — 요구사항대로 처음부터 맞게 짠다.
  2. 탄탄함 — 경계값 · 잘못된 입력 · 동시 실행에서 깨지지 않고, 나중에 고쳐도 다른 곳이 깨지지 않는다.
  3. 틀린 코드는 실행 중이 아니라 컴파일할 때 잡힌다.
- **빠르다** = 실행 속도와 컴파일 속도 둘 다. AI는 컴파일 → 에러 읽기 → 고치기를 수십 번 돌기 때문에, 컴파일 속도는 곧 AI 개발 속도다.
- **안전하다** = 4절의 보장 G1~G7.

### 판단 순서 (가안)

목표끼리 부딪히면 이 순서로 고른다.

1. 보장(G1~G7) — 양보하지 않는다.
2. AI가 짠 코드의 정확도 · 탄탄함
3. 실행 속도
4. 컴파일 속도

## 4. 꼭 지킬 보장

아래 일곱 가지는 도담의 핵심이다. 어기는 코드는 **컴파일되지 않는다.**

| # | 보장 | 막는 사고 |
|---|---|---|
| G1 | **메모리 안전, 데이터 경쟁 없음, 정의되지 않은 동작 없음** | 버퍼 오버플로, 해제 후 사용, 동시 실행에서 값이 깨지는 버그 |
| G2 | **권한 선언** — 함수가 쓰는 부수효과(`Db` · `Net` · `Fs` · `Proc` · `Env` · `Secret` · `Mail` · `Clock` · `Random` · `Log` …)를 시그니처에 적는다. 적지 않은 권한을 쓰면 에러. 권한은 호출한 쪽으로 전파된다 | AI가 몰래 외부로 데이터를 보내는 코드, 리뷰에서 놓친 부수효과 |
| G3 | **실행 대상의 경계** — 권한마다 돌 수 있는 실행 대상이 정해져 있다. 웹에서는 `Db` · `Fs` · `Secret`이 서버, `Dom`이 브라우저다. 대상에 없는 권한에 닿는 코드는 그 대상으로 빌드되지 않는다(서버 전용 코드는 브라우저 번들에 들어갈 수 없다). `Secret<T>`는 직렬화가 안 돼서 응답 · 화면 · 로그로 나갈 수 없다 | 비밀키 · DB 코드가 프론트에 노출되는 사고, 실행 대상에 없는 기능을 쓰는 코드 |
| G4 | **신뢰 경계와 오염 추적** — 외부 입력(요청 본문 · 폼 · URL · 헤더 · 파일 · 명령줄 인자 · 환경 변수 · 외부 API 응답)은 `Untrusted<T>`다. 검증을 거쳐야 `T`가 된다. SQL · HTML · 셸 · URL · 로그 같은 출력 지점은 안전한 타입만 받는다 | SQL 인젝션, XSS, 명령 주입, 경로 탐색, 로그 위조 |
| G5 | **숨은 동작 없음** — null 없음(`Option`), 예외 없음(`Result`), 암묵 형변환 없음, 전역 가변 상태 없음, 매크로 · 리플렉션 · 몽키패치 · 연산자 오버로딩 없음 | 코드만 봐서는 알 수 없는 동작, AI의 잘못된 추론 |
| G6 | **같은 일은 한 가지 방법으로** — 같은 일을 하는 문법은 하나. 공식 포매터 하나, 설정 없음 | 코드마다 다른 스타일, 일관성 붕괴 |
| G7 | **재현 가능한 빌드와 패키지 권한** — 잠금 파일 필수. 패키지는 자기가 쓰는 권한을 선언하고, 사용하는 쪽이 승인한다. 승인되지 않은 권한을 쓰면 빌드 실패. 설치 스크립트 없음 | 공급망 공격, "내 컴퓨터에선 됐는데" |

**접근 정책도 필수다(웹).** 화면에서 부를 수 있는 서버 함수는 모두 `access public` 또는 `access auth(역할)`을 적어야 한다. 적지 않으면 컴파일 에러다. 권한 검사 누락(웹 보안 사고 1위)을 문법으로 막는다.

**탈출구는 하나만 둔다.** 정말 필요할 때 `trust "사유" { … }` 블록으로 규칙을 넘을 수 있다. 사유 문자열이 필수이고, 모든 `trust` 블록은 사유와 함께 보안 보고서(5절)에 올라간다. 사람이 승인하기 전에는 배포 빌드에 들어가지 않는다. 설정 파일로 보안 규칙을 끄는 방법은 없다.

## 5. 사람이 보는 것 — 결과물과 보안 보고서

사람은 코드를 읽지 않는다. 대신 컴파일러가 **보안 보고서**를 낸다(`dodam report`). JSON이 먼저이고, 사람이 보는 화면은 그걸 렌더링한 것이다.

보고서에 담는 것:

- 이 프로그램이 쓰는 권한 전체와, 각 권한을 쓰는 곳 (G2)
- 데이터가 밖으로 나가는 곳 — 접속하는 주소 · 메일 · 로그 (G2 · G3)
- 화면에서 부를 수 있는 서버 함수와 각 접근 정책 (4절)
- 외부 입력이 들어오는 곳과 거치는 검증 (G4)
- `trust` 블록과 사유 (4절)
- 패키지와 패키지 권한 (G7)
- 테스트와 DodamBench 보안 테스트 결과

**사람이 승인하는 것은 보안 변화뿐이다.** 지난 배포보다 권한 · 나가는 곳 · `access public` 함수 · `trust` 블록 · 패키지 권한이 늘었으면, 보고서가 그 차이만 따로 보여 준다. 승인된 상태는 잠금 파일에 남고, 승인되지 않은 변화가 있으면 배포 빌드가 실패한다. 개발 빌드는 막지 않는다. 늘지 않은 변화와 그 밖의 코드 변경은 승인이 필요 없다.

사람이 코드를 읽지 않으므로 **컴파일러의 버그가 곧 보안 구멍**이다. 검사기 자체를 퍼징하고, 보장마다 그 보장을 깨려는 테스트 모음을 컴파일러와 함께 둔다.

## 6. AI를 위한 설계

| # | 원칙 | 기준 |
|---|---|---|
| A1 | **명세가 프롬프트 하나에 들어간다** | 언어 명세 + 표준 라이브러리 요약이 **1만 토큰 이하**. 릴리스마다 재고, 넘으면 릴리스하지 않는다 |
| A2 | **기계가 읽는 진단** | 모든 에러는 JSON(코드 · 위치 · 원인 · 수정안 · 관련 명세 절)으로 나온다. 사람이 보는 메시지는 그걸 렌더링한 것이다 |
| A3 | **에러 코드는 고정 ID** | 에러 코드마다 문서 페이지와 예시가 있다. AI가 검색하고 인용할 수 있다 |
| A4 | **MCP 서버 기본 제공** | `compile` · `check` · `test` · `explain_error` · `spec_lookup` · `run_bench` 도구를 언어와 함께 배포한다 |
| A5 | **국소 추론** | 파일 하나, 함수 하나만 읽어도 이해된다. import는 명시적으로만 하고 와일드카드 import는 없다 |
| A6 | **버전 안정성** | 1.0 이후 문법은 하위 호환한다. 바꿔야 하면 자동 마이그레이션 도구를 함께 낸다. AI가 옛 문법을 섞어 써도 컴파일러가 고쳐 준다 |
| A7 | **계약을 코드에** | 함수에 `requires` · `ensures`와 속성 테스트를 붙인다. 처음에는 테스트로 검사하고, 나중에 정적 검증으로 넓힌다 |
| A8 | **AI가 이미 아는 생김새에서 출발** | 사람이 읽기 좋은지는 따지지 않는다. 기본 가설은, TypeScript · Rust · Kotlin 계열 모양이어야 학습 데이터가 없는 새 언어라도 AI가 기존 지식을 빌려 쓴다는 것이다. 문법 후보에 사람 가독성을 버린 AI 전용 모양도 넣어 DodamBench로 비교하고, 숫자가 나은 쪽을 고른다 |
| A9 | **빠른 컴파일** | 컴파일 → 고치기 반복이 빨라야 AI가 빨리 맞춘다. 목표(가안): 한 파일 고친 뒤 다시 검사 1초 이내, 깨끗한 빌드는 Go와 같거나 빠르게 |

진단 예시:

```json

```

## 7. 메모리 모델 — 가장 먼저 정할 것

안전 · 속도 · AI 정확도가 가장 세게 부딪히는 곳이다. 수동 메모리 관리는 하지 않으므로(11절) 후보는 넷이다.

| 후보 | 대표 언어 | 예상 장점 | 예상 약점 |
|---|---|---|---|
| 추적 GC | Go · Java · C# | AI가 신경 쓸 것이 적다 | 메모리를 더 쓰고 지연이 튄다. 임베디드에 맞지 않는다 |
| 소유권 + 수명 | Rust | 가장 빠르고 데이터 경쟁이 없다 | 수명 · 빌림 에러를 AI가 자주 틀린다 |
| 자동 참조 카운트 | Swift · Koka | GC 멈춤이 없다 | 순환 참조 처리, 카운트 비용 |
| 가변 값 의미론 | Hylo | 참조를 드러내지 않아 수명 표기가 거의 없다 | 쓰인 사례가 적다 |

표의 장단점은 예상이다. 2027년 1~2월에 후보마다 작은 시제품을 만들어 DodamBench로 정확도 · 탄탄함 · 실행 속도를 재고 고른다. 결과 숫자는 결정 문서에 남긴다.

## 8. 첫 분야: 웹 — 서버와 화면을 코드 한 벌로

- 한 모듈 안에 서버 함수와 화면 코드가 같이 있을 수 있다. **컴파일러가 권한을 보고 실행 위치를 정한다.**
- 화면에서 `server fn`을 부르면 컴파일러가 API를 만든다. HTTP 엔드포인트, 직렬화, 입력 검증, CSRF 방어가 자동으로 붙는다.
- 서버에 도착한 인자는 자동으로 `Untrusted`가 되고, 함수 선언에 적힌 타입으로 검증 코드가 생성된다. 사람이 검증을 빼먹을 수 없다.
- 화면은 **상태 · 메시지 · update · view** 구조다(Elm 방식). view는 순수 함수이고 타입이 있는 HTML 트리를 돌려준다. 숨은 상태가 없다.

문법 맛보기 (임시 — 실제 문법은 1단계에서 벤치마크로 정한다):

```dodam
type SignupForm = { email: Email, name: Text(1..40) }

server fn signup(form: SignupForm) -> Result<UserId, SignupError>
  access public
  uses Db, Mail
{
  let id = Db.insert(users, { email: form.email, name: form.name })?
  Mail.send(form.email, welcomeMail(form.name))?
  Ok(id)
}

page Signup {
  state = { form: SignupForm.empty, status: Idle }

  update(state, msg) = match msg {
    Submit       => (state with { status: Sending }, call signup(state.form) then Done)
    Done(result) => state with { status: Finished(result) }
  }

  view(state) = form(onSubmit: Submit) [
    textField(state.form.email, label: "이메일"),
    textField(state.form.name, label: "이름"),
    button("가입하기"),
  ]
}
```

이 코드에서 컴파일러가 하는 일:

- `signup`은 `Db` · `Mail`을 쓰므로 서버에서만 돈다. 화면 번들에는 호출 코드만 들어간다.
- `call signup(...)`을 보고 `POST` 엔드포인트와 검증 코드를 만든다.
- `Email`은 검증을 거쳐야만 만들어지는 타입이다. `Text(1..40)`은 길이 검사가 자동으로 붙는다.
- `access public`이 없으면 컴파일되지 않는다.

## 9. 스스로 자라는 구조

도담은 AI가 스스로 다듬는다. 문법 세부 · 표준 라이브러리 · 진단 · 규칙을 AI가 제안하고, 숫자가 나아지면 AI가 병합한다. 다만 보안을 약하게 만드는 변화는 AI 혼자 넣을 수 없다. 사람이 이 언어에서 바라는 것이 보안이고, 보안 규칙을 바꿀 수 있는 AI는 규칙을 약하게도 바꿀 수 있기 때문이다.

### 세 층

| 층 | 내용 | 누가 병합하나 |
|---|---|---|
| 1. 핵심 | G1~G7, 타입 · 권한 · 오염 추적 규칙 | 사람이 승인. AI가 설계 문서(RFC)와 벤치 숫자를 낸다 |
| 2. 규칙 묶음 | 린트 · 보안 규칙 | 추가 · 조이기는 AI가 병합. 완화 · 삭제는 사람이 승인 |
| 3. 지식과 문법 세부 | 표준 라이브러리, 예제 모음, 에러 메시지, 수정안, 1.0 전의 문법 세부 | AI가 병합 |

### AI가 혼자 병합하는 조건

아래를 모두 채워야 한다. 하나라도 못 채우면 사람이 보안 보고서와 벤치 비교를 보고 승인한다.

1. DodamBench 보안 지표가 비공개 과제를 포함해 하나도 나빠지지 않는다.
2. 정확도 · 탄탄함이 나빠지지 않고, 정확도 · 탄탄함 · 속도 가운데 하나 이상이 나아진다. 실행 · 컴파일 속도는 5%보다 많이 나빠지지 않는다(가안).
3. 핵심(G1~G7)을 건드리지 않는다.
4. 규칙 완화 · 삭제가 없고, 보안 보고서에 새로 늘어나는 항목(권한 · `trust` 블록 · 패키지 권한)이 없다.

### 개선 루프

1. 벤치마크 · 퍼저 · 실제 사용에서 실패를 모은다.
2. 실패를 유형별로 분류한다.
3. AI가 그 실패를 막는 규칙 · 함수 · 메시지를 제안한다. **실패를 재현하는 테스트를 같이 낸다.**
4. 지금까지 모인 코드 전체에 돌려서 오탐률을 잰다.
5. 병합 조건을 채우면 AI가 병합하고, 채우지 못하면 사람 승인을 기다린다.
6. 검사를 모두 통과한 코드는 예제 모음에 쌓여 다음 AI의 참고 자료가 된다.

### 조여지기만 하는 원칙 (래칫)

- 규칙을 **추가 · 조이는** 건 병합 조건을 채우면 AI가 한다.
- 규칙을 **완화 · 삭제**하려면 사유 문서와 함께, 벤치마크 보안 지표가 나빠지지 않았다는 비교 결과를 붙여야 한다. AI는 완화를 제안할 수는 있지만 승인 · 병합할 권한은 없다.

### 검사기 속이기 방지

- 벤치마크 과제 일부(30%)는 **비공개로 보관**한다. 개선 루프는 공개 과제로만 돌리고, 평가는 비공개 과제로 한다. AI가 공개 과제에만 맞춰지는 걸 잡아낸다.
- 여러 회사의 AI 모델로 같이 잰다. 한 모델에만 맞춰진 언어가 되지 않게 한다.
- 언어를 고치는 AI는 비공개 과제를 볼 수 없고, 측정 도구와 기존 과제를 고칠 수 없다. 과제는 늘릴 수만 있고, 지우거나 고치려면 사람 승인이 필요하다.

## 10. 벤치마크 — DodamBench

0단계의 핵심 산출물이다. **언어보다 먼저 만든다.**

### 과제

흔한 프로그래밍 과제 100개를 분야별로 둔다. 첫 분야가 웹이어도 처음부터 다른 분야를 섞어서, 문법이 웹에만 맞춰지지 않게 한다.

| 분야 | 예 | 개수(가안) |
|---|---|---|
| 웹 서버 · 화면 | 회원가입 · 로그인 · 파일 업로드 · 검색 · 페이지 나누기 · 관리자 권한 · 결제 웹훅 · 이메일 발송 | 40 |
| CLI · 데이터 처리 | 로그 분석기 · CSV/JSON 변환기 · 설정 파일 검사기 | 20 |
| 네트워크 · 동시성 | 프록시 · 작업 큐 · 속도 제한기 · 채팅 서버 | 20 |
| 시스템 · 성능 | 파일 동기화 · 압축 · 파서 · 캐시 | 20 |

과제 하나의 구성:

- 자연어 요구사항
- 숨긴 기능 테스트, 숨긴 경계값 테스트(빈 입력 · 최댓값 · 잘못된 형식)
- 숨긴 보안 테스트(인젝션 · XSS · 권한 우회 · 비밀 노출 · SSRF · 경로 탐색 · 메모리 오류)
- 성능 부하 시나리오
- **수정 요청** 한두 개 — 구현이 끝난 뒤 요구사항을 바꾸고, 고친 뒤 기존 테스트가 깨지는지 본다.

테스트는 **언어와 무관하게 바깥에서** 본다. HTTP 요청 · 브라우저 조작 · 명령줄 입출력 · 파일 결과만 보므로 모든 언어를 같은 테스트로 잰다.

### 비교 대상

각 목표에서 1등일 만한 언어를 반드시 넣는다.

- **핵심 7개 (매번 잰다)**: Python · TypeScript · Java · C# · Go · Rust · C++
- **참고 11개 (단계가 끝날 때마다 잰다)**: C · Kotlin · Swift · Zig · PHP · Ruby · Elixir · Haskell · OCaml · Gleam · MoonBit

| 목표 | 1등 후보 |
|---|---|
| AI 학습 데이터가 가장 많음 | Python · TypeScript |
| 보안 | Rust |
| 실행 속도 | C++ · Rust · Go |
| 컴파일 속도 | Go |
| 웹 실무 주류 | Java · C# · PHP |
| 가까운 경쟁자 | MoonBit · Gleam |

- 웹 과제는 언어마다 가장 많이 쓰는 프레임워크 하나로 고정한다(예: TypeScript는 Next.js, Java는 Spring Boot, Python은 FastAPI).
- 그 분야에서 쓸 수 없는 조합은 뺀다(예: 브라우저 화면 과제는 브라우저에서 도는 언어만).
- 같은 과제를 AI 모델 3개 이상으로, 모델마다 3번씩 푼다.

### 재는 것

| 목표 | 지표 |
|---|---|
| 정확도 | 첫 시도 컴파일 성공률, 기능 테스트 통과율, 경계값 테스트 통과율 |
| 탄탄함 | 수정 요청 뒤 깨진 기존 테스트 수, 퍼징으로 찾은 크래시 수, 통과할 때까지 고친 횟수 |
| 보안 | 보안 테스트 통과율(남은 취약점 수) |
| 실행 속도 | 응답 시간(p50 · p99), 초당 처리량, 메모리, 시작 시간, 실행 파일 · 브라우저 번들 크기 |
| 컴파일 속도 | 깨끗한 빌드 시간, 한 파일 고친 뒤 다시 빌드하는 시간 |
| 비용 | AI가 쓴 토큰과 시간 |

실행 속도와 컴파일 속도는 모든 언어를 같은 기계 · 같은 부하 도구로 잰다.

### 공개와 목표

- **공개 70개 / 비공개 30개.**
- **1.0 목표 (가안)**: 비교 대상 가운데 목표마다 1등인 언어와 견준다.
  - 보안: 남은 취약점이 가장 적은 언어보다 더 적게
  - 정확도 · 탄탄함: 가장 높은 언어와 같거나 높게
  - 실행 속도: Go와 같거나 빠르게, Rust · C++보다 느려도 1.5배 안
  - 컴파일 속도: Go와 같거나 빠르게

## 12. 기술 선택 (기본값)

| 항목 | 선택 | 이유 |
|---|---|---|
| 컴파일러 구현 | Rust | 컴파일러 도구가 풍부하고, 컴파일러 자체도 메모리 안전 |
| 서버 · CLI 출력 | 네이티브 기계어. 개발 빌드는 Cranelift, 배포 빌드는 LLVM | Cranelift는 컴파일이 빠르고 LLVM은 실행이 빠르다. 컴파일 속도와 실행 속도를 둘 다 잡는다 |
| 브라우저 출력 | WASM + 얇은 JS 연결 코드 | 브라우저에서 기계어에 가깝게 도는 형식. DOM 접근은 JS 연결 코드를 거친다 |
| 격리 실행 | WASM (WASI) | 언어에서 선언한 권한을 실행 환경에서도 한 번 더 막는다 |
| 라이선스 | MIT OR Apache-2.0 | Rust와 같은 이중 라이선스. 특허 보호(Apache)와 단순함(MIT)을 둘 다 준다 |
| 저장소 | GitHub 공개 | 위치(조직 / 개인 계정)는 미정. `dodam-lang` · `dodamlang` 조직 이름은 비어 있다(2026-10-28 확인) |
| 웹사이트 | `dodam-lang.org` (추천, 미구매) | `rust-lang.org`처럼 언어 사이트에 흔한 형태이고 GitHub 조직 이름과 맞는다. `dodam.com` · `.dev` · `.org` · `.app` · `.ai` · `.kr`은 이미 등록돼 있다 |

v0.1의 첫 출력이던 TypeScript는 뺐다. 기존 JS 라이브러리를 빌려 쓰기는 쉽지만 실행 속도 목표와 맞지 않는다.
