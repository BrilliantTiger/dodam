# 도담 헌장 — 0단계 설계 초안

- 판: v0.1 (2026-10-28)
- 상태: 초안. 검토하면서 고친다. 공개 전에 영어판을 만든다.

## 1. 한 줄 정의

**AI가 짜고 사람이 검토하는 웹 애플리케이션을 위한 언어.** 서버와 화면을 코드 한 벌로 쓰고, 보안 규칙은 컴파일러가 강제하며, 그 규칙은 시간이 갈수록 조여지기만 한다.

> A language for web applications written by AI and reviewed by humans: one codebase for server and browser, security enforced by the compiler, and rules that only ever tighten.

## 2. 이름

**도담 (Dodam).** "도담도담"은 아이가 탈 없이 튼튼하게 자라는 모양이다. 이 언어도 탈(보안 사고) 없이, 스스로 자란다. 영어로 읽으면 끝의 `dam`(막는 벽)이 위험한 데이터 흐름을 막는다는 뜻으로도 읽힌다.

- 명령어: `dodam`
- 파일 확장자: `.dodam`

## 3. 누구를 위한 언어인가

- **1차 사용자는 AI 코딩 에이전트**다. 2차 사용자는 그 코드를 검토하는 사람이다.
- **대상 분야는 웹 서비스**다. API 서버와 브라우저 화면을 같이 다룬다.
- 설계 판단이 갈리면 "AI가 덜 헷갈리고, 사람이 덜 읽어도 되는 쪽"을 고른다.

## 4. 꼭 지킬 보장

아래 일곱 가지는 도담의 핵심이다. 어기는 코드는 **컴파일되지 않는다.**

| # | 보장 | 막는 사고 |
|---|---|---|
| G1 | **메모리 안전, 정의되지 않은 동작 없음** | 버퍼 오버플로, 해제 후 사용 |
| G2 | **권한 선언** — 함수가 쓰는 부수효과(`Db` · `Net` · `Fs` · `Secret` · `Mail` · `Clock` · `Random` · `Log` …)를 시그니처에 적는다. 적지 않은 권한을 쓰면 에러. 권한은 호출한 쪽으로 전파된다 | AI가 몰래 외부로 데이터를 보내는 코드, 리뷰에서 놓친 부수효과 |
| G3 | **서버와 화면의 경계** — 권한마다 실행 위치가 정해져 있다(`Db` · `Fs` · `Secret`은 서버, `Dom`은 브라우저). 서버 전용 권한에 닿는 코드는 브라우저 번들에 들어갈 수 없다. `Secret<T>`는 직렬화가 안 돼서 응답 · 화면 · 로그로 나갈 수 없다 | 비밀키 · DB 코드가 프론트에 노출되는 사고 |
| G4 | **신뢰 경계와 오염 추적** — 외부 입력(요청 본문 · 폼 · URL · 헤더 · 파일 · 외부 API 응답)은 `Untrusted<T>`다. 검증을 거쳐야 `T`가 된다. SQL · HTML · 셸 · URL · 로그 같은 출력 지점은 안전한 타입만 받는다 | SQL 인젝션, XSS, 명령 주입, 경로 탐색, 로그 위조 |
| G5 | **숨은 동작 없음** — null 없음(`Option`), 예외 없음(`Result`), 암묵 형변환 없음, 전역 가변 상태 없음, 매크로 · 리플렉션 · 몽키패치 · 연산자 오버로딩 없음 | 코드만 봐서는 알 수 없는 동작, AI의 잘못된 추론 |
| G6 | **같은 일은 한 가지 방법으로** — 같은 일을 하는 문법은 하나. 공식 포매터 하나, 설정 없음 | 코드마다 다른 스타일, 일관성 붕괴 |
| G7 | **재현 가능한 빌드와 패키지 권한** — 잠금 파일 필수. 패키지는 자기가 쓰는 권한을 선언하고, 사용하는 쪽이 승인한다. 승인되지 않은 권한을 쓰면 빌드 실패. 설치 스크립트 없음 | 공급망 공격, "내 컴퓨터에선 됐는데" |

**접근 정책도 필수다.** 화면에서 부를 수 있는 서버 함수는 모두 `access public` 또는 `access auth(역할)`을 적어야 한다. 적지 않으면 컴파일 에러다. 권한 검사 누락(웹 보안 사고 1위)을 문법으로 막는다.

**탈출구는 하나만 둔다.** 정말 필요할 때 `trust "사유" { … }` 블록으로 규칙을 넘을 수 있다. 사유 문자열이 필수이고, 컴파일러가 모든 `trust` 블록을 목록으로 내서 리뷰 대상으로 집계한다. 설정 파일로 보안 규칙을 끄는 방법은 없다.

## 5. AI를 위한 설계

| # | 원칙 | 기준 |
|---|---|---|
| A1 | **명세가 프롬프트 하나에 들어간다** | 언어 명세 + 표준 라이브러리 요약이 **1만 토큰 이하**. 릴리스마다 재고, 넘으면 릴리스하지 않는다 |
| A2 | **기계가 읽는 진단** | 모든 에러는 JSON(코드 · 위치 · 원인 · 수정안 · 관련 명세 절)으로 나온다. 사람이 보는 메시지는 그걸 렌더링한 것이다 |
| A3 | **에러 코드는 고정 ID** | 에러 코드마다 문서 페이지와 예시가 있다. AI가 검색하고 인용할 수 있다 |
| A4 | **MCP 서버 기본 제공** | `compile` · `check` · `test` · `explain_error` · `spec_lookup` · `run_bench` 도구를 언어와 함께 배포한다 |
| A5 | **국소 추론** | 파일 하나, 함수 하나만 읽어도 이해된다. import는 명시적으로만 하고 와일드카드 import는 없다 |
| A6 | **버전 안정성** | 1.0 이후 문법은 하위 호환한다. 바꿔야 하면 자동 마이그레이션 도구를 함께 낸다. AI가 옛 문법을 섞어 써도 컴파일러가 고쳐 준다 |
| A7 | **계약을 코드에** | 함수에 `requires` · `ensures`와 속성 테스트를 붙인다. 처음에는 테스트로 검사하고, 나중에 정적 검증으로 넓힌다 |
| A8 | **익숙한 생김새** | 문법은 TypeScript · Rust · Kotlin 계열의 익숙한 모양으로 만든다. 학습 데이터가 없는 새 언어라도 AI가 기존 지식을 빌려 쓸 수 있게 한다 |

진단 예시:

```json
{
  "code": "DD-E0412",
  "message": "서버 전용 권한 Db를 쓰는 함수 loadUser가 화면 코드에서 직접 호출됐습니다.",
  "at": "app/profile.dodam:18:5",
  "fixes": [
    { "title": "loadUser를 server fn으로 선언해서 API로 호출", "edit": "…" }
  ],
  "spec": "§4.2 실행 위치"
}
```

## 6. 서버와 화면을 코드 한 벌로

- 한 모듈 안에 서버 함수와 화면 코드가 같이 있을 수 있다. **컴파일러가 권한을 보고 실행 위치를 정한다.**
- 화면에서 `server fn`을 부르면 컴파일러가 API를 만든다. HTTP 엔드포인트, 직렬화, 입력 검증, CSRF 방어가 자동으로 붙는다.
- 서버에 도착한 인자는 자동으로 `Untrusted`가 되고, 함수 선언에 적힌 타입으로 검증 코드가 생성된다. 사람이 검증을 빼먹을 수 없다.
- 화면은 **상태 · 메시지 · update · view** 구조다(Elm 방식). view는 순수 함수이고 타입이 있는 HTML 트리를 돌려준다. 숨은 상태가 없다.

문법 맛보기 (임시 — 실제 문법은 1단계에서 벤치마크로 정한다):

```dodam
type SignupForm = { email: Email, name: Text(1..40) }

server fn signup(form: SignupForm) -> Result<UserId, SignupError>
  access public
  uses Db, Mail
{
  let id = Db.insert(users, { email: form.email, name: form.name })?
  Mail.send(form.email, welcomeMail(form.name))?
  Ok(id)
}

page Signup {
  state = { form: SignupForm.empty, status: Idle }

  update(state, msg) = match msg {
    Submit       => (state with { status: Sending }, call signup(state.form) then Done)
    Done(result) => state with { status: Finished(result) }
  }

  view(state) = form(onSubmit: Submit) [
    textField(state.form.email, label: "이메일"),
    textField(state.form.name, label: "이름"),
    button("가입하기"),
  ]
}
```

이 코드에서 컴파일러가 하는 일:

- `signup`은 `Db` · `Mail`을 쓰므로 서버에서만 돈다. 화면 번들에는 호출 코드만 들어간다.
- `call signup(...)`을 보고 `POST` 엔드포인트와 검증 코드를 만든다.
- `Email`은 검증을 거쳐야만 만들어지는 타입이다. `Text(1..40)`은 길이 검사가 자동으로 붙는다.
- `access public`이 없으면 컴파일되지 않는다.

## 7. 스스로 자라는 구조

도담의 "자라는" 부분은 언어 핵심이 아니라 그 바깥에서 일어난다. 보안 규칙을 바꿀 수 있는 AI는 규칙을 약하게도 바꿀 수 있기 때문이다.

### 세 층

| 층 | 내용 | 누가 바꾸나 |
|---|---|---|
| 1. 핵심 | G1~G7, 타입 · 권한 · 오염 추적 규칙 | 사람만. 설계 문서(RFC) 필요 |
| 2. 규칙 묶음 | 린트 · 보안 규칙 | AI가 제안, 사람이 승인 |
| 3. 지식 | 표준 라이브러리의 안전한 함수, 예제 모음, 에러 메시지, 수정안 | AI가 제안, 자동 검증을 통과하면 사람이 승인 |

### 개선 루프

1. 벤치마크 · 퍼저 · 실제 사용에서 실패를 모은다.
2. 실패를 유형별로 분류한다.
3. AI가 그 실패를 막는 규칙 · 함수 · 메시지를 제안한다. **실패를 재현하는 테스트를 같이 낸다.**
4. 지금까지 모인 코드 전체에 돌려서 오탐률을 잰다.
5. 사람이 승인하면 다음 버전에 들어간다.
6. 검사를 모두 통과한 코드는 예제 모음에 쌓여 다음 AI의 참고 자료가 된다.

### 조여지기만 하는 원칙 (래칫)

- 규칙을 **추가**하는 건 사람 승인 한 번이면 된다.
- 규칙을 **완화 · 삭제**하려면 사유 문서와 함께, 벤치마크 보안 지표가 나빠지지 않았다는 비교 결과를 붙여야 한다. AI는 완화를 제안할 수는 있지만 승인 · 병합할 권한은 없다.

### 검사기 속이기 방지

- 벤치마크 과제 일부(30%)는 **비공개로 보관**한다. 개선 루프는 공개 과제로만 돌리고, 평가는 비공개 과제로 한다. AI가 공개 과제에만 맞춰지는 걸 잡아낸다.
- 여러 회사의 AI 모델로 같이 잰다. 한 모델에만 맞춰진 언어가 되지 않게 한다.

## 8. 벤치마크 — DodamBench

0단계의 핵심 산출물이다. **언어보다 먼저 만든다.**

- **과제**: 웹 서비스에서 흔한 기능 100개. 회원가입 · 로그인 · 파일 업로드 · 검색 · 페이지 나누기 · 관리자 권한 · 결제 웹훅 · 이메일 발송 등.
- **과제 하나의 구성**: 자연어 요구사항 + 숨긴 기능 테스트 + 숨긴 보안 테스트(인젝션 · XSS · 권한 우회 · 비밀 노출 · SSRF · 경로 탐색).
- **비교 대상**: TypeScript(Next.js) · Java(Spring Boot) · Python(FastAPI), 그리고 도담.
- **재는 것**
  1. 첫 시도 컴파일 성공률
  2. 기능 테스트 통과율
  3. 보안 테스트 통과율(남은 취약점 수)
  4. 통과할 때까지 고친 횟수
  5. 쓴 토큰과 시간
- **공개 70개 / 비공개 30개.**
- **1.0 목표 (가안)**: TypeScript 대비 남은 취약점 90% 감소, 기능 통과율은 같거나 높게, 고친 횟수는 같거나 적게.

## 9. 하지 않을 것

- 시스템 프로그래밍 · 임베디드 · 게임 엔진 · 고성능 수치 계산 (1.0 전까지)
- 수동 메모리 관리
- 매크로 · 리플렉션 · 사용자 정의 연산자
- 기존 언어와의 문법 호환 (생김새만 익숙하게 한다 — A8)
- 처음부터 자체 런타임이나 VM 만들기 (기존 런타임을 빌려 쓴다 — 10절)
- 설정으로 보안 끄기

## 10. 기술 선택 (기본값)

| 항목 | 선택 | 이유 |
|---|---|---|
| 컴파일러 구현 | Rust | 컴파일러 도구가 풍부하고, 컴파일러 자체도 메모리 안전 |
| 첫 출력 | TypeScript | 서버(Bun)와 브라우저에서 모두 돈다. 기존 라이브러리를 빌려 쓸 수 있다 |
| 이후 출력 | WASM (WASI) | 언어에서 선언한 권한을 실행 환경에서도 한 번 더 막는다 |
| 라이선스 | MIT OR Apache-2.0 | Rust와 같은 이중 라이선스. 특허 보호(Apache)와 단순함(MIT)을 둘 다 준다 |
| 저장소 | GitHub 공개 | 위치(조직 / 개인 계정)는 미정. `dodam-lang` · `dodamlang` 조직 이름은 비어 있다(2026-10-28 확인) |
| 웹사이트 | `dodam-lang.org` (추천, 미구매) | `rust-lang.org`처럼 언어 사이트에 흔한 형태이고 GitHub 조직 이름과 맞는다. `dodam.com` · `.dev` · `.org` · `.app` · `.ai` · `.kr`은 이미 등록돼 있다 |
